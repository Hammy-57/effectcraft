# GPU reports: #580, #591 and #613

## #591: retained memory and allocation failure

The staging-buffer cache previously retained two buffers **for every distinct readback size**;
the transparent-image cache was limited by entry count, rather than bytes, and was omitted from
purge. The reuse pool also left textures waiting for an encoder outside its budget and purge.
Pending reuse now counts against the pool budget and is dropped on purge. Both auxiliary caches
now have total byte budgets, follow the layer-cache preference, and are cleared by
`GpuContext::clear_uploads`. Zero memory budget disables retention, not rendering. Integrated
adapters retain at most 256 MiB of uploads, 128 MiB of free working textures and 16 MiB in each
auxiliary cache; these are retention limits, not guarantees about transient working memory or
driver allocations. Discrete adapters keep their existing upload/pool caps.

Native `Gpu::within_memory` now drains both internal and out-of-memory errors even when a
native mapped-at-creation allocation unwinds. It returns a diagnostic to the caller's existing
CPU fallback and clears retained resources. It does not turn a failed render into a success.

Focused regressions:
- `shared_memory_cache_budgets_follow_preferences_and_have_lower_caps`
- `pool_pending_reuse_is_bounded_and_purge_cannot_repopulate_it`
- `auxiliary_caches_are_bounded_across_sizes_and_purged` (tiny budget, changing dimensions)
- `within_memory_contains_native_allocation_unwind_and_drains_scopes`

These changes alone do not prove the original Snapdragon project works. The application's
separate compositor/presentation devices and UI fallback need integration validation; whole
presentation-device recovery remains a different concern. Adreno hardware validation is pending.

## #613: DirectX compiler

Windows MSVC x64 builds enable wgpu's `static-dxc` feature. Its default `Auto` compiler then
finds the linked DXC instead of falling through to FXC, which the issue reproduces aborting while
compiling `pointwise`. This applies to both desktop and headless users of the GPU crate. No shader
or effect is removed. `WGPU_DX12_COMPILER=fxc` remains an explicit diagnostic override where the
host honors it.

The lockfile pins `mach-dxcompiler-rs` and `lhash`; the compiler wrapper is MIT licensed. The
wrapper's build script downloads a pinned, SHA-256-verified native DXC archive on Windows, so
Windows packaging needs network access for that first build. wgpu does not support static DXC
on Windows ARM64; this change does not claim to fix that configuration.

`dx12_auto_compiler_builds_compositor_with_linked_dxc` requires a Windows DX12 adapter (set
`EFFECTCRAFT_REQUIRE_GPU=1` to forbid a skip). It compiles every compositor kernel, executes RGB inversion through `pointwise`, and checks
the pixels read back. A Mac compile check cannot establish DX12 acceptance.

## #580: chromatic aberration plus Pan/Tilt

The report (10 October 2026) has no platform, image dimensions, project or crash log. The
published `v0.7.0` source **does** expose `centerTilt` / `centerPan`. Fork commit `77c769d8`
replaced that older chromatic algorithm and its angular controls with the measured spherical
channel-split model and Point of Interest / field-of-view controls. That commit is present in
this checkout but absent from the `v0.7.0` release, explaining the differing UI controls.

The former GPU path normalized `direction - center * cos(theta)` after a separate cross-product
threshold; the new path shares CPU/GPU setup and guards the length of the vector it actually
divides by. Reading that difference is not enough to attribute the reported crash to it.
The historical CPU/GPU tests covered Center Tilt 30 / Center Pan -60; no original crash was
reproduced in this investigation.

`chromatic_direction_control_crosses_seams_and_poles` checks corresponding spherical center
directions using the current Point of Interest control, with odd-sized mono and stereo images,
against CPU rendering. This is a bounded diagnostic regression, not proof of the reporter's
crash or its resolution. Exact input dimensions, release/backend and crash diagnostics remain
necessary to identify that root cause. No speculative angular-coordinate correction was made.
